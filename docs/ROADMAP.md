# Roadmap and grant milestones

The proof of concept answers one question first: can a public transaction corpus encode wallet-relevant safety semantics in a reproducible way?

## Milestone 1 — public proof

- Six legacy and v0 fixtures.
- SPL Token and Token-2022 coverage.
- Strict JSON schema, deterministic analyzer, CLI, tests, and CI.
- No backend, database, website, wallet connection, RPC dependency, or private keys.

## Milestone 2 — ecosystem pilot

- Expand to 30–50 reviewed fixtures, including multisig, durable nonce, address lookup tables, swaps, compressed assets, and Token-2022 extensions.
- Publish the schema and fixtures as a versioned npm package.
- Add an adapter interface that lets wallets map SafeSign findings to their own warnings without exposing user data.
- Recruit two wallet, simulator, or explorer teams to run the corpus and document usability feedback.

## Milestone 3 — durable public good

- Add conformance reports generated by participating projects themselves.
- Establish a review and disclosure process for fixture contributions.
- Commission an independent security review of parsers and fixture generation.
- Transfer maintenance to a small multi-project working group if ecosystem adoption warrants it.

## Funding posture

Grant funding should pay for ecosystem validation, expanded coverage, integration adapters, documentation, and review—not a speculative consumer website. The current repository is intentionally a working artifact that can be evaluated before any funding decision.
